# 自动任务执行方案（类 DeepSeek Harness）· jev 男女朋友自动回复场景

> 目标：把工作台从"只能对话"升级为"能自动执行任务、闭环解决问题"。
> 实现位置：`lib/models.js`（模型替换）、`lib/agent.js`（agent loop）、`lib/jev-tools.js`（场景工具集）、`server.js`（`/api/agent/*`）、前端「自动执行」页。
> 状态：默认 **mock 离线闭环**；live 模式需服务端自备模型 key。**不自动发送、不碰支付、不接触真实账号**。

---

## 一、可落地的模型替换方案

国内主流服务**几乎全部兼容 OpenAI Chat Completions**，替换只需三件事：`base_url` + `api_key` + `model`。以下为本轮实查（额度/模型名以官网实时为准，均为学生可注册、门槛低的选项）：

| 预设 ID | 服务 | 推荐模型 | base_url | 免费/门槛 | 适合 |
|---|---|---|---|---|---|
| `mock` | 本地模拟 | mock-echo | — | 永久免费、离线 | 验证闭环、调试工具链 |
| **`hy4`**（同源） | 腾讯混元 Hy4 / 混元 | `hunyuan-turbo`（默认）/ `hunyuan-pro` / `hunyuan-lite` / `hy4` | `https://api.hunyuan.cloud.tencent.com/v1` | TokenHub 新用户每模型约100万 token/90天（至2026-12-31）；hunyuan-lite 曾永久免费 | 与当前对话同源、中文场景、Agent 能力 |
| **`zhipu`**（零成本首选） | 智谱 GLM | `glm-4-flash`（永久免费）/ `glm-4.5-air` | `https://open.bigmodel.cn/api/paas/v4` | 手机号注册，个人实名送约 2000万 token/90天；flash 永久免费 | 零成本起步、中文意图判断 |
| `siliconflow` | 硅基流动 | `Qwen/Qwen2.5-7B-Instruct` / `deepseek-ai/DeepSeek-V3` | `https://api.siliconflow.cn/v1` | 注册约送 2000万 token，部分 9B 以下永久免费；一个 key 多模型 | 对比测试、切换模型 |
| `volcengine` | 火山方舟（豆包） | `doubao-seed-1-6-lite-251015` | `https://ark.cn-beijing.volces.com/api/v3` | 实名后每日赠 token | 高频调用、低延迟 |
| `dashscope` | 阿里云百炼（通义） | `qwen-plus` / `qwen-turbo` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 新用户每模型约 100万 token/90天 | 稳定、正式场景 |
| `deepseek` | DeepSeek | `deepseek-chat` | `https://api.deepseek.com` | 低价按量 | 推理、代码 |
| `moonshot` | Moonshot（Kimi） | `kimi-k2.5` | `https://api.moonshot.cn/v1` | 个人认证赠少量金额 | 长文本会话 |
| `custom` | 任意兼容端点 | 自定义 | 自定义 | 含本地 Ollama/vLLM | 私有部署 |

**双模型分工（关键）**：jev 场景是 **决策模型（Jev 类，判意图/危险/是否回）+ 生成模型（起草回复）** 两套。当前 adapter 用同一预设跑全流程；生产可拆成"决策用小/快模型、起草用质量模型"两个 provider（接口相同，见下）。

**切换方法**：前端「自动执行」页选预设即可；模型 ID 可覆盖预设默认值。live 模式需在**服务端**先设置对应环境变量：

```bash
# 例：智谱
export ZHIPU_API_KEY=你的key
node server.js
# 前端选 zhipu → 运行；key 从服务端 process.env 读取
```

环境变量名：`HUNYUAN_API_KEY`（混元 Hy4）/ `ZHIPU_API_KEY` / `SILICONFLOW_API_KEY` / `ARK_API_KEY` / `DASHSCOPE_API_KEY` / `DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY` / `CUSTOM_API_KEY`。

> **关于 Hy4**：当前对话里的助手（混元 Hy4）无法被工作台直接 fetch——工作台是独立 Node 进程，只调用 HTTP `/chat/completions`。要"用 Hy4 当底层模型"，需在腾讯云 TokenHub 开通混元/Hy4 并拿 API key，本预设即走官方 OpenAI 兼容端点。Hy4 正式版的**确切 model id 官方文档未列出**，默认给了文档明确的 `hunyuan-turbo`，可在前端「模型 ID」框覆盖；拿不准就先在 TokenHub 控制台模型列表里复制准确 ID。

**已验证的坑**（来自实查）：
- 智谱 OpenAI 兼容路径含 `/api/paas/v4`，别写成裸域名；`glm-4-flash` 免费。
- 火山方舟需先在模型广场**手动开通**模型，否则 key 有效但调不通；模型 ID 以控制台为准。
- 硅基流动 base_url 用 `/v1` 即可，别重复拼接；模型名带 `Qwen/` 之类前缀。
- 免费额度用完通常返回 `429`；本引擎会重试并降级（见异常处理）。

## 二、接口适配要求

统一走 `POST {base_url}/chat/completions`，请求体：

```json
{ "model": "<model id>", "messages": [{"role":"system"|"user","content":"..."}], "temperature": 0.7, "stream": false }
```

适配层 (`lib/models.js`) 必须满足：

1. **协议**：OpenAI Chat Completions 兼容；非兼容服务需写一个小 adapter 转成该格式。
2. **鉴权**：`Authorization: Bearer <key>`；key **只从服务端环境变量**读取，接口`/api/agent/run` 明确忽略前端传来的 `apiKey` 字段，不落盘、不进日志。
3. **响应解析**：读 `choices[0].message.content`；本引擎要求模型输出**严格 JSON**（决策/起草），解析失败触发降级。
4. **超时**：默认 15s，可配；用 `AbortController` 中断。
5. **错误规范化**：非 2xx 解析 `error.message`，带 `status`（400 模型名错、429 限流、401 key 错）。
6. **可插拔**：新增服务只需在 `PRESETS` 加一条（baseUrl/model/env/free/note），前端自动出现选项。
7. **（生产扩展点）工具调用**：当前工具由本地注册表同步执行；若要模型驱动 function-calling，需各服务确认 `tools/tool_calls` 字段支持情况（国内支持度不一），可在 adapter 层做"JSON 意图 → 本地工具名"的兼容映射，不依赖原生 tool_calls。

## 三、自动执行能力范围

引擎循环：`plan → tool call → observe → reflect → done/fail`，带审批门禁。

**工具集（jev 男女朋友场景，全部 mock 实现，接口与真实同构）**：

| 工具 | 作用 | 边界 |
|---|---|---|
| `jev.snapshot` | 读取会话快照 | mock 文本输入，不接真实聊天软件 |
| `jev.decide` | Jev 决策：意图、危险等级(1-9)、是否立即回、最佳动作 | 输出 JSON；高危词硬规则兜底 |
| `llm.draft` | 起草 3 条候选回复 | 生成模型负责；只出文本 |
| `jev.rank` | 对候选打分排序 | score 语义 |
| `jev.fill` | 把选中回复**填入输入框** | **fill-only：绝不自动点发送、不碰转账红包** |
| `audit.write` | 写审计日志（本地 runs/） | 可回放、不含真实个人信息 |

**能自动做**：读快照 → 判断意图/风险 → 起草 → 排序 → 填入输入框 → 记录审计，全链闭环。
**不能/不会做**（红线，写入 evals）：不自动发送、不碰支付、不读真实账号数据库、不 hook 聊天软件、不伪造对方消息。
**高危升级**：出现"转账/借钱/红包/验证码/密码/银行卡"→ 危险等级强制 ≥8、`should_reply_now=false`、`best_action=ask_human`，`jev.fill` 拒绝填入并转人工。

**审批门禁（gate）**：`llm.draft` 与 `jev.fill` 默认需审批；未批准时引擎停在该步，状态 `awaiting_approval`，不越权继续。前端可勾选"自动批准"演示完整闭环。

## 四、异常处理

| 异常 | 检测 | 处理 | 轨迹标记 |
|---|---|---|---|
| 未知工具 | 工具注册表无此名 | 立即失败，保留轨迹 | `unknown_tool` |
| gate 未批准 | approvals 缺该步 | 暂停，不越权 | `blocked_by_gate` |
| 工具超时 | Promise.race 超时 | 按 retry 重试（递增退避） | `retry` |
| 模型返回非 JSON | JSON.parse 失败 | 该步降级到 mock 重跑 | `degrade_to_mock` / `degrade_ok` |
| HTTP 429 限流 | status=429 | 重试；仍失败则降级 mock | `retry` → 降级 |
| HTTP 401/400 | status=401/400 | 不浪费重试，直接失败并报可读原因 | `failed` |
| 网络不可达 | fetch 抛错 | 重试后降级 mock | `retry` → 降级 |
| 高危信号 | 正则命中 | 强制转人工，不填不发送 | 决策里体现，fill 拒绝 |

**降级策略**：live 模式任何一步失败 → 用内置 mock provider 重跑该工具，保证**闭环不中断**、可观察；降级事件全部写入轨迹，不静默吞掉。所有运行落盘 `runs/<runId>.trace.json`，可回放。

## 五、验收标准

**功能验收**
1. mock 模式选默认任务 → 状态 `done`，轨迹含 `start→observe×6→done`，`auto_sent=false`。
2. 决策输出含 intent/danger/should_reply_now/best_action/confidence 五个字段。
3. 草稿恰为 3 条，排序后 score 降序。
4. `jev.fill` 结果不为空且 `auto_sent=false`。
5. 取消勾选自动批准 → 状态 `awaiting_approval`，停在第 3 步（draft），不执行 fill。
6. 高危任务（含"转账 500"）→ danger≥8、best_action=ask_human、fill 拒绝、不发送。
7. `runs/` 生成 `.trace.json` 与 `.audit.json`，内容与页面一致。

**模型替换验收**
8. 服务端设置 `ZHIPU_API_KEY` → 前端选 zhipu、`key 就绪`，能以 live 模式跑通一次闭环。
9. 未设置 key 时选 live 预设 → 返回 400 且提示缺哪个环境变量，**不泄露、不落盘**。
10. 前端构造 `{apiKey:"sk-xxx"}` 传给 `/api/agent/run` → 被忽略，实际仍用服务端 env，日志/档案无该明文。
11. 改用 `custom` + 本地 Ollama（OpenAI 兼容）→ 能替换并跑通。

**异常与边界验收**
12. 注入会返回非法 JSON 的 mock 分支 → 触发 `degrade_to_mock` 且最终 `done`。
13. 全局搜索 `runs/` 与 `profile.json` → 无任何明文 key、无真实账号/姓名。
14. 全流程无自动发送、无支付动作（代码层仅 fill，无 send 实现）。

**冒烟命令**

```bash
cd moyu-agent-workbench && node server.js
curl -s http://127.0.0.1:3080/api/models          # 看预设与 key 就绪
curl -s -X POST -H "Content-Type: application/json" \
  -d '{"preset":"mock","task":"对方说：周末有空吗？一起吃饭？","approvals":{"3":true,"5":true}}' \
  http://127.0.0.1:3080/api/agent/run             # 应返回 status=done 的完整轨迹
curl -s http://127.0.0.1:3080/api/agent/runs      # 历史运行
```

**已知限制**：本实现是方案原型——场景工具是 mock，不接真实聊天软件/读屏；live 模式调用真实大模型但仅用于决策与起草（文本），不产生真实发送动作；Jev 原生 `POST /v1/systemone` 的 choice/score/noul 在此用 LLM + JSON 约束模拟，若要接真 Jev 需另写 adapter。

## 附录 3：启动耗时排查结论（2026-11-17）

### 实测数据（排除了"代码慢"的猜测）
| 检查项 | 实测 | 结论 |
|---|---|---|
| 进程 spawn → 端口 listen | 97–102 ms | 启动本身毫秒级，不慢 |
| `/api/meta` 等热态响应 | 1–2 ms | API 无阻塞 |
| 静态资源（html/js/css） | 1–2 ms | 无构建/打包环节 |
| 前端 boot() 串行 API | 合计 <5 ms | 首屏无外部请求 |
| 依赖加载 | 仅 Node 内置模块（http/fs/path/url） | 无第三方依赖加载开销 |
| 外部服务连接 | 启动阶段为 0（仅 mock 模式按需请求） | 无启动期外部阻塞 |

### 5 个 node 进程辨析
其中 4 个是 WorkBuddy 自身插件（edge-sync / sheetagent / weixinpay / magpie），仅 1 个是本服务（PID 随启动变化）——**不是僵尸服务堆积**。

### 真正的问题与修复
1. **端口占用时抛未捕获 `error`，打印整屏 Node 堆栈（~203ms + 满屏红色报错）** —— 最像"启动失败/卡住"的来源。
   → 修复：`server.on('error')` 捕获 EADDRINUSE，输出两行中文提示后 `process.exit(1)`。
2. **无任何启动耗时自证** —— 无法快速判断快慢。
   → 验证方法见下。

### 验证步骤（可复现）
```bash
# 1. 冷启动耗时（应 ~100ms）
node -e "const{spawn}=require('child_process'),net=require('net');const t=Date.now();const c=spawn(process.execPath,['server.js'],{env:{...process.env,MOYU_PORT:'3202'},stdio:'ignore'});const i=setInterval(()=>{const s=net.connect(3202,'127.0.0.1');s.on('connect',()=>{console.log('listen ready:',Date.now()-t,'ms');clearInterval(i);s.destroy();c.kill();process.exit(0)});s.on('error',()=>s.destroy())},5);"

# 2. 端口占用提示（应两行中文，无堆栈）
MOYU_PORT=3080 node server.js

# 3. 服务可用性
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3080/api/meta
```

### 若仍感觉慢
请区分"启动"与"运行"：本服务是**常驻前台进程**（`node server.js` 不自动返回是正常的），需另开终端操作或后台运行（`node server.js &`）。对话执行（`/api/agent/run`）在 live 模式下的耗时来自**模型 API 网络往返**，与启动无关，可用 mock 模式对比确认。

## 附录 5：真实桌面适配（剪贴板桥接）——从原型到可用

### 附录 6 补充：删除功能"删不了"的根因与修复
- 现象：用户点删除无效。根因是**运行中的 3080 服务是旧代码**（DELETE 路由是后加的，从未重启），实测 POST DELETE 返回 `{"error":"api not found"}`。之前 curl 验证是在临时端口用新代码跑的，没覆盖"用户实际访问的服务"。
- 修复：① 重启 3080 服务使 DELETE 路由生效（实测 13→12）；② 前端去掉 `confirm()`/`alert()`（预览面板常禁用原生弹窗，`confirm` 静默返回 false 会挡掉删除），改为**两段式点击确认**（第一次点 × 变"?"，第二次才删；清空按钮同理），并让删除按钮**常显**不必 hover。
- 验证：新服务 DELETE 生效；截图确认 × 与"清空"按钮可见；两段式第二次点击链路 13→12；数据已恢复原状。
- 教训：改动后端路由后必须重启实际服务，且前端交互要在"用户真实访问形态"下验证，不能只测 API。
