# 「摸鱼 agent」初步方案 v0.2（GitHub 选型落地版）

> 性质：纯方案 v0.2，不含实现代码。基于「作业版块」模板（`jupyter-lab-report` skill）抽象。
> 本轮做了 8 次真实联网检索/抓取；所有 star 数为 2026-09/10 多来源快照，彼此差异较大，**以 GitHub 实时页为准**。
> 更新：2026-11-17

## 〇、架构定位

用户明确：摸鱼 agent 本身是一个**和 Claude Code 同类、要 API key 的 agent**；三版块以 `SKILL.md`（开放格式）挂在上面。检索证实 `SKILL.md` 可被 OpenCode / Goose / Codex CLI / Gemini CLI 直接读取，故模板不必绑死 Claude Code。

```
摸鱼 agent = 类 Claude Code harness（吃 LLM API key）
           + 三份 SKILL.md（作业版块模板实例化）
           + 共享决策内核 Jev（独立 API key / 本地替代）
           + profile.json（凭据只存引用）
```

**harness 选型**：首选 `anomalyco/opencode`（MIT，BYOK 或 Ollama，原生读 SKILL.md + MCP）；备选 `openai/codex`、`google-gemini/gemini-cli`（Apache-2.0）；国内备选 Qwen Code / Kimi CLI。
**两把 key**：LLM key（harness 推理/起草）与 Jev key（决策内核）分开登记、各存引用。

## 一、三版块（各六项 + 最优开源项目）

### 1. 刷课 `course_auto`（S3 / P1）
- **目标**：授权下无人值守推进播放，产出可核验完成记录；不改成绩、不产证书，异常暂停交还用户。
- **场景**：登录/静音倍速/跳弹题/断点续播；滑块验证暂停→人工处理→恢复；产出章节+时长+异常交接清单。
- **能力**：Playwright/CDP 浏览器自动化、DOM 视频识别、状态机续播、异常人工接管、进度自检、反检测节流（P2）。
- **I/O**：profile 凭据引用 + 课程 URL + 播放参数 → 进度记录 + 日志 + 异常交接单。
- **复用**：直接复用 SOP/profile/CLI 链/evals/pack；扩展 `course.*`、逐章节进度 audit、接管状态机；全新浏览器内核与守护。本质差异：一次性交付 vs 长时状态机。
- **最优项目**：`CXRunfree/Autovisor`（首选执行内核，Playwright 全套能力 + config 外置）；`browser-use/jev-ultrafast`（决策增强）；油猴脚本（平台 adapter 参考）。⚠️ 作者公告佛系更新，维护是最大变量。

### 2. jev 自动回复对象 `jev_reply`（S4 / P2，解锁不抢跑）
- **定义更新**：jev = 用于决策的大模型（TypeSafe Jev 及开源生态），非早期猜测的 IM 平台/联系人/bot 框架。
- **目标**：Jev 先判意图/风险/是否该回，生成模型起草，默认人工确认后发送；可审计、可停止。
- **场景**：读屏→Jev 判意图/危险等级(1–9)/紧迫度/最佳动作→生成 3 条→Jev 排序→只填输入框不代发。
- **能力**：Jev 决策（choice/score/noul，`POST /v1/systemone`）、LLM 起草（第二把 key）、读屏/IM 适配、会话记忆、频控审计、一键停止。
- **I/O**：profile 引用 + 人设话术 + 规则 + 对话快照 → 草稿（默认）或确认后发送 + 审计日志。
- **复用**：复用 profile/ask-first/doctor/evals/pack；扩展 `messaging.*`、长驻守护、合规自检、草稿双模；全新 Jev 内核（已下沉共享）、人格、记忆。
- **最优项目**：`jev-chat/jev-chat-jarvis`（首选标杆，MIT，fill-only 不代发，直接印证草稿优先）；决策内核 `TypeSafe Jev`（托管，闭源，$0.042/百万输入 token，厂商自报）或 `nokia-applied-research/AnyJev`（Apache-2.0，任意 LLM 转决策模型、无需训练，学生零预算首选）/ `ollaya-dev/ollaya`（本地 drop-in）；⚠️ `laya` 零样本≈随机，需微调，非即插即用。
- **关键**：Jev 只决策不写文本 → 必然是 Jev（决策）+ 生成 LLM（起草）双模型组合，因此需要两套 key。

### 3. 毕设 / 竞赛 `project_lab`（S2 / P0）
- **澄清**：modex 非单一项目，是一批数模全流程 agent/skill；整个赛道已从自研框架转向 **SKILL.md + Harness** 范式，印证「作业版块」方向正确。
- **目标**：选题到交付全流程确定性 SOP，产出可复现可核验包；论文每个数字可追溯、引用须支撑论点。
- **场景**：检索文献→实验出图→audit 校验图有产物→LaTeX/Typst 编译与引用校验→模拟评审/rebuttal→打包。
- **能力**：检索与文献、实验执行、中文排版编译、反幻觉门控（数字挂 R-xxx、引用挂 S-xxx）、自动审稿、版本快照。
- **I/O**：选题/数据/模板/profile → 论文 PDF + 代码图表 + 引用库 + 答辩材料 + 复现说明 + 自检报告。
- **复用**：三版块中最高，SOP/profile/命令链/assets/pdf/pack 几乎逐节映射；扩展文献检索、实验执行、引用数字追溯 audit、review/rebuttal；全新研究闭环。
- **最优项目**：`qing1989620/workbuddy-modex`（OMMW，首选工程底座，核心 MIT，Research Core 单一事实源 + 8 条反幻觉规则 + doctor/verify/render/parity/package 命令链 + 双渲染 + WorkBuddy adapter）；`jihe520/MathModelAgent`（首选能力参考，~5.1K，multi-LLM/HIL 六动作/9 步验收，禁商用，只参考方法）；`logic1241/xiaohudie-math-modeling`（素材库，16 算法模板+4 LaTeX 模板）；`Escap1ng/math-modeling-skill`（MIT，≥85 分评分闭环）；`modex-mh-agent`（愿景参考，成熟度待验）。

## 二、共享内核与档案

- **必须下沉**：profile/ask-first 引擎、CLI 链骨架与质量闸门、evals 框架、`CredentialResolver`（Q4 确认后只换后端）、日志审计基座。
- **可选适配器**（≥2 版块真实复用再提升）：浏览器内核、LLM 客户端、联网检索、Jev 决策内核。
- **版块内聚**：刷课播放器状态机、jev 人格/记忆/频控、project 检索/实验/编译/review、各版块领域 audit。
- **profile 命名空间**：`common.*`（machine/identity/credentials 只存引用）、`course.*`、`messaging.*`（send_policy 默认 draft_only）、`project.*`。
- **档案五规则**：分区前缀强制；同名靠前缀隔离；覆盖优先级 实例ID > 分区 > common（同分区内生效）；凭据收敛 `common.credentials.*` 引用；check 阶段 schema 校验（顺带修复「占位档案能通过 check」）。
- **补充约束**：`messaging.*` 支持多凭据引用；run/listen 按 `account_id` 显式绑定；pack 不带出引用清单；doctor 必须覆盖内部适配器可达性。

## 三、迭代优先级

S0 模板加固（P0）→ S1 共享内核+命名空间（P0/P1）→ S2 project_lab 接 OMMW（P0）→ S3 course_auto 接 Autovisor（P1）→ S4 jev 接 jarvis 范式（P2 解锁不抢跑）→ S5 增值（P2）。排序理由：依赖优先 + 复用度优先 + 风险递增（读屏隐私面最敏感）。
